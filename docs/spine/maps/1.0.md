# Map

## Destination

Spine 1.0: a production-grade public toolkit for one human and their agent fleet,
on one repo, on any OS, in any harness. Installable, documented, and verified on
ubuntu/macos/windows, shipped with a trust chain: owner-checked advance, every
mutation through the engine, reason and human-intervention recorded,
per-profile self-approval. Fleet-scale and dynamic skill resolution are the
next map, not this one.

## Notes

Origin: 2026-09-21 audit of an outside-advisor conversation about spine
(claim-by-claim against the tree) plus grilling rounds 1–2 (nine decisions,
all accepted by the owner). Predecessor: `productionize.md` (0.3.0, fully
resolved). This map is the 1.0 effort; 23 tickets live in
`docs/spine/tickets/` (16–38).

## Decisions so far

1. **1.0 = public OSS standard + trust-chain headline.** Installable,
   documented, CI across OSes, 1.0 tag. Fleet-scale is the NEXT map.
2. **Positioning:** one human + their agent fleet, one repo, any OS.
   Multi-human / multi-machine is out of scope.
3. **Trust chain (Tier A):** owner-checked advance · every mutation through
   the engine · `reason` + `HumanInterventionRequired` wired · per-profile
   self-approval (software: `by ≠ Owner`; non-software: self allowed; always
   recorded) · Claim as one module.
4. **Engineering (Tier C):** ruff (lint + format) · pyright (gradual) · CI
   ubuntu/macos/windows × Python 3.11–3.13 · coverage floor 70→85 ·
   tag→publish (PyPI trusted publishing) · in-repo user guide.
5. **Skill binding in 1.0:** static concern→skill + auditable wire changes.
   `spine wire --suggest` resolver = 1.1 candidate (fog).
6. **No agent concept in spine** — documented deliberate boundary. Fleet =
   identities (`SPINE_USER`) + event trail.
7. **No roles model.** Keep current HITL (typed exit 6) + decision 3 policy.
   Human = sole approver of record.
8. **`done` stays terminal.** spine tracks work, not deploys. `released` /
   production state = fog (resisted even for the next map).
9. **1.0 ships = trust chain + engineering + docs** (positioning, deliberate
   boundaries, user guide, spec alignment) + 1.0 tag + publish + changelog.
   One-board-scan is excluded (perf, not trust).

## Route

Repo convention: `Blocked by` is a single-value field (doctor resolves one
reference and clears it when that blocker resolves). Multi-gate tickets carry
the last-completing gate in the field and the full gate list in the body
(`Gates:` line).

Frontier rule: a ticket whose field blocker is resolved enters the frontier.
Dispatch the builder one ticket at a time, wave by wave; the `builder` persona
(local Qwen) takes execution tickets, `--verify "uv run pytest"`.

## Not yet specified (fog)

- `spine wire --suggest`: goal→capability resolver (1.1 candidate).
- `released` / production state after `done` (fog; resisted for the next map too).
- Multi-human / multi-machine coordination (v2, a new product axis, not debt).
- One-board-scan perf (excluded from 1.0: perf, not trust).

## Out of scope

- Hosted orchestration service.
- Multi-repo / cross-machine coordination.
- Auth / SSO.
- Agent capability matching (deliberate boundary, not debt).
- Shipped 0.3.0 history (changelog records the delta; no rewrites).
